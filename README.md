# Варіант 10. Агент навчального помічника «Study Buddy»

Навчальний агент допомагає студентам: пояснює концепції, генерує тестові питання, перевіряє відповіді, створює плани навчання.

## Опис проєкту

Проєкт на базі LangGraph та локальної LLM gemma4:e4b.

Основна мета системи — автоматизована генерація та багаторівнева методична й математична перевірка навчальних задач (зокрема з математики та геометрії для студентів першого кусу). Генератор створює задачі, а Оцінювач перевіряє їх. Для виставлення ойфнки в LMS використовується HITL (підтвердження оцінки викладчем).

## Інструкція запуску
 
1. Клонувати репозиторій: `git clone https://github.com/youryharchenko/task001-agent-StudyBuddy.git`.
2. Перейти в директорію: `cd task001-agent-StudyBuddy`.
3. Встановити залежності: `pip install -r requirements.txt`.
4. Налаштувати адресу сервісу OLLAMA: `OLLAMA_SERVER_IP="..."`.
5. Створити векторну базу ChromaDB: `python build_kb.py`.
6. Запустити агента на тест-кейсах: `python test_.....py`.

В прєкті використано Ollama модель *gemma4:e4b*, в ChromaDB викороистано *BAAI/bge-m3*

## Відповіді на питання

### 1. Як agentic RAG допомагає агенту знаходити правильний матеріал курсу?

Завдяки Agentic RAG навчальний агент діє як досвідчений викладач чи асистент: аналізує суть питання, шукає в декількох розділах конспекту, перевіряє, чи знайдене має сенс.

### 2. Чому виставлення оцінки потребує HITL?

* Захист від галюцинацій та помилок LLM.
* Відповідальність та академічна етика.
* Врахування індивідуального контексту.
* Захист від Prompt Injection та маніпуляцій.

### 3. Як Plan-and-Execute структурує створення навчального плану?

* Гарантує дотримання дидактичних принципів: від простого до складного, з чітким зв'язком між темами.
* Викладач може перевірити та затвердити високорівневий план до того, як система почне робити деталізацію.

### 4. Опишіть різницю між tool (generate_question) та RAG (пошук у конспектах).

*RAG* відповідає за те, **ЧОМУ** саме навчають (контент курсу), а інструмент *generate_question* — за те, **ЯК** це перевірити (методичний артефакт).

### 5. Як checkpointer зберігає прогрес студента між сесіями?

Checkpointer у LangGraph реалізує механізм персистентності (persistence), зберігаючи повний стан графа (State) після кожного виконаного кроку (super-step) у зовнішньому сховищі SQLite. Це дозволяє студентській сесії зберігати свій прогрес між виходами з системи, відновлювати діалог з того самого місця та підтримувати паттерн Human-in-the-Loop (наприклад, для перевірки завдань викладачем).

Ключові механізми: Thread ID (Ідентифікатор сесії), Снапшот стану (State Snapshot), Відновлення сесії (Checkpoint Retrieval).
